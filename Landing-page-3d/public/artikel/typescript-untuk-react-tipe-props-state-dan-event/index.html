TypeScript untuk React: Tipe Props, State, dan Event

TypeScript menangkap kesalahan sebelum kode berjalan: salah ketik nama props, lupa menangani kasus data kosong, mengirim string ke fungsi yang mengharapkan angka. Di proyek React yang tumbuh, ia menjadi dokumentasi hidup sekaligus jaring pengaman refactoring. Tidak perlu menguasai semua fitur; sedikit pola cukup untuk 90% pekerjaan.

Sebaiknya sudah paham: React dasar, JavaScript modern

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • mengetik props, state, dan event handler di komponen React
  • memakai union type untuk memodelkan status dan varian
  • memakai generics pada hook dan komponen daftar
  • membedakan interface dan type serta memilih yang tepat
  • menghindari any dan memakai penyempitan tipe (narrowing)

Menyempitkan tipe (narrowing) dengan aman

any dan data luar

Hindari any: ia mematikan pemeriksaan tipe. Bila tipe benar-benar tidak diketahui (misalnya hasil JSON dari server), pakai unknown lalu persempit atau validasi dengan pustaka seperti Zod. Tipe TypeScript hilang saat runtime, jadi data dari luar tetap harus divalidasi.

Latihan mandiri
1. Ketik props komponen Tombol dengan variant "utama" atau "sekunder" dan onClick opsional.
type Props = { variant: "utama" | "sekunder"; onClick?: () => void; children: ReactNode }
2. Mengapa tipe TypeScript tidak melindungi dari respons API yang salah bentuk?
Tipe dihapus saat kompilasi; data runtime dari jaringan harus divalidasi (misalnya dengan Zod) sebelum dipercaya.
3. Buat tipe Hasil untuk operasi yang berhasil dengan data atau gagal dengan pesan.
type Hasil = { ok: true; data: T } | { ok: false; pesan: string }
4. Kapan menulis tipe secara eksplisit dan kapan membiarkannya disimpulkan?
Eksplisit pada batas (props, fungsi publik, nilai awal ambigu); biarkan disimpulkan untuk variabel lokal yang jelas.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Ketik props dengan type; gunakan union literal untuk nilai terbatas; children bertipe ReactNode.
  • useState bila nilai awal tidak memberi tahu tipe; tipe event berasal dari React.
  • Discriminated union dan generics membuat keadaan mustahil tidak dapat ditulis dan komponen dapat dipakai ulang.
  • Hindari any; validasi data eksternal karena tipe tidak ada saat runtime.

Tanya jawab

Apakah TypeScript memperlambat pengembangan?
Awalnya sedikit, lalu mempercepat karena autocompletion, refactoring aman, dan kesalahan tertangkap lebih awal, terutama pada tim dan proyek yang tumbuh.
Bagaimana memulai proyek React dengan TypeScript?
Vite menyediakan templat: npm create vite@latest nama -- --template react-ts.
Apakah wajib mengetik semuanya?
Tidak; mulai dari props, data dari API, dan fungsi bersama. Aktifkan strict mode agar pemeriksaan bermakna.
