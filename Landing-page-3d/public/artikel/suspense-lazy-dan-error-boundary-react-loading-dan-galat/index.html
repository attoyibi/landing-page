Suspense, lazy, dan Error Boundary di React

Setiap aplikasi punya dua kejadian yang harus ditangani: sesuatu belum siap (memuat) dan sesuatu rusak (galat). Tanpa pola yang baik, kode penuh pemeriksaan if (memuat) dan if (galat) di setiap komponen. React menyediakan Suspense untuk yang pertama dan error boundary untuk yang kedua, keduanya sebagai pembungkus deklaratif.

Sebaiknya sudah paham: komponen React, async/await, useEffect

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • memakai React.lazy dan Suspense untuk memecah bundel (code splitting)
  • menempatkan batas Suspense dengan fallback yang masuk akal
  • membuat error boundary dan memahami apa yang tidak ditangkapnya
  • menggabungkan keduanya untuk pengalaman memuat dan gagal yang rapi
  • memahami Suspense untuk data dan hook use pada React 19

Code splitting dengan lazy

Secara bawaan, semua komponen masuk ke satu bundel JavaScript. Halaman yang jarang dibuka (pengaturan, laporan) membuat pengguna mengunduh kode yang mungkin tak pernah dipakai. React.lazy memuat komponen saat pertama kali dibutuhkan, memakai import() dinamis.

Suspense: di mana menaruhnya

  • Satu batas besar di sekitar halaman: sederhana, tetapi seluruh halaman diganti fallback saat satu bagian menunggu.
  • Beberapa batas kecil di sekitar bagian independen (sidebar, daftar, panel): bagian lain tetap tampil, pengalaman lebih halus.
  • Fallback yang baik menyerupai bentuk akhir (kerangka/skeleton) agar tata letak tidak melompat (CLS rendah).
  • Suspense bersarang: fallback terdekat di atas komponen yang menunggu yang dipakai.

Error boundary: jaring pengaman render

Layar putih

Tanpa error boundary, galat saat render di satu komponen kecil akan membuat seluruh aplikasi menjadi layar kosong. Error boundary menangkap galat di pohon di bawahnya dan menampilkan UI cadangan. Hingga kini error boundary harus berupa class component; pustaka react-error-boundary menyediakan versi siap pakai dengan API fungsional.

Yang TIDAK ditangkap error boundary

Tidak ditangkapTangani dengan
Galat di event handler (onClick)try/catch di handler
Kode asinkron (setTimeout, fetch, promise)try/catch atau .catch; simpan galat di state
Galat saat rendering di serverMekanisme galat framework
Galat di error boundary itu sendiriBoundary di tingkat lebih atas

Menggabungkan keduanya

Suspense untuk data dan hook use

Suspense tidak hanya untuk lazy. Dengan pustaka atau framework yang mendukungnya (TanStack Query dengan useSuspenseQuery, Next.js, React Router), komponen dapat "menunggu" data dan Suspense menampilkan fallback. React 19 menambahkan hook use(promise) yang membaca Promise di dalam render dan menangguhkan komponen sampai selesai; bila Promise ditolak, galatnya ditangkap error boundary terdekat. Janji untuk use harus dibuat di luar render (misalnya di Server Component, atau di-cache), bukan dibuat baru setiap render.

Latihan mandiri
1. Ubah impor halaman Pengaturan menjadi lazy dan bungkus dengan Suspense.
const Pengaturan = lazy(() => import("./Pengaturan")); <Suspense fallback={<p>Memuat...</p>}><Pengaturan /></Suspense>
2. Mengapa galat di onClick tidak masuk ke error boundary?
Error boundary hanya menangkap galat saat render; handler berjalan di luar render sehingga perlu try/catch.
3. Di mana sebaiknya menaruh beberapa error boundary?
Di sekitar bagian independen (widget, panel) agar kerusakan satu bagian tidak mematikan seluruh halaman.
4. Apa keuntungan code splitting bagi pengguna?
Bundel awal lebih kecil sehingga halaman pertama termuat lebih cepat; kode halaman lain diunduh saat dibutuhkan.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • React.lazy + import() memecah bundel; Suspense menampilkan fallback selama menunggu.
  • Beberapa batas Suspense kecil memberi pengalaman lebih halus; fallback menyerupai konten akhir.
  • Error boundary menangkap galat render dan menampilkan UI cadangan; ia tidak menangkap event handler atau kode asinkron.
  • Gabungkan boundary (luar) dengan Suspense (dalam); React 19 use() membaca Promise saat render.

Tanya jawab

Apakah lazy bekerja dengan SSR?
Ya, melalui framework yang mendukung streaming SSR dan Suspense (Next.js, React Router framework); konfigurasi sendiri lebih rumit.
Bagaimana melaporkan galat produksi?
Kirim dari componentDidCatch atau onError ke layanan seperti Sentry agar Anda tahu kegagalan yang dialami pengguna.
Apakah Suspense menggantikan status loading manual?
Untuk data yang mendukungnya, ya; Anda tidak perlu isLoading di setiap komponen karena fallback ditangani di batas di atasnya.
