Firebase untuk Pemula: Auth, Firestore, dan Hosting

Firebase dari Google menyediakan backend siap pakai: login pengguna, database real-time, penyimpanan file, dan hosting. Untuk prototipe, aplikasi mobile Flutter, atau tim tanpa developer backend khusus, Firebase bisa memangkas waktu berminggu-minggu. Syaratnya: memahami cara kerjanya, terutama security rules.

Cara berpikir data di Firestore

Firestore menyimpan dokumen (mirip objek JSON) di dalam koleksi. Tidak ada JOIN. Karena itu data disusun sesuai cara layar membacanya, kadang dengan sengaja menduplikasi sedikit data.

kelas (koleksi)
 └─ python-dasar (dokumen)
     ├─ judul: "Python Dasar"
     ├─ pengajar: { id: "u7", nama: "Muchson" }   ← disalin agar tidak perlu query kedua
     └─ peserta (subkoleksi)
         └─ u12 (dokumen) { nama: "Ani", progres: 60 }
import { collection, query, where, orderBy, onSnapshot } from 'firebase/firestore';

const q = query(
  collection(db, 'kelas'),
  where('aktif', '==', true),
  orderBy('mulai')
);
// real-time: dipanggil ulang setiap ada perubahan
onSnapshot(q, snap => {
  const daftar = snap.docs.map(d => ({ id: d.id, ...d.data() }));
  console.log(daftar);
});

Security rules: bagian yang paling penting

Aplikasi web dan mobile berbicara langsung ke Firestore dari perangkat pengguna. Satu-satunya penjaga adalah security rules. Rules yang longgar berarti siapa pun yang tahu konfigurasi proyek Anda bisa membaca atau menghapus seluruh database.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // profil hanya bisa dibaca dan diubah pemiliknya
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // kelas boleh dibaca semua user login, diubah hanya admin
    match /kelas/{id} {
      allow read: if request.auth != null;
      allow write: if request.auth.token.admin == true;
    }
  }
}
Jebakan mode uji

Mode uji Firestore memberi akses terbuka dengan batas waktu. Jangan biarkan aturan "allow read, write: if true" sampai produksi. Uji rules dengan Emulator Suite sebelum deploy.

Biaya: dihitung per operasi

Firestore menagih berdasarkan jumlah baca, tulis, dan hapus dokumen, plus penyimpanan dan transfer data. Ada kuota gratis harian. Desain yang boros, misalnya membaca 1.000 dokumen untuk menampilkan satu angka total, bisa membuat tagihan melonjak saat pengguna bertambah.

Kapan Firebase tepat, kapan tidak

Firebase juga kini menyediakan Data Connect berbasis PostgreSQL bagi yang butuh model relasional. Alternatif serupa yang open source adalah Supabase (PostgreSQL) dan Appwrite.

Tanya jawab

Apakah Firebase gratis?
Ada paket Spark gratis dengan kuota tertentu. Untuk Cloud Functions dan pemakaian lebih besar, perlu paket Blaze (bayar sesuai pemakaian). Pasang anggaran dan peringatan tagihan di Google Cloud.
Firestore atau Realtime Database?
Untuk proyek baru, Firestore umumnya disarankan karena query dan skalanya lebih baik. Realtime Database masih berguna untuk data sangat sederhana dengan latensi rendah.
Apakah config Firebase di frontend rahasia?
Tidak. Konfigurasi itu memang publik. Keamanan bergantung pada security rules, App Check, dan pembatasan API key.
