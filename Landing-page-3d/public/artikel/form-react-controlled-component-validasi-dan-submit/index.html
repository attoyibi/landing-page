Form di React: Controlled Component, Validasi, dan Submit

Form adalah tempat aplikasi bertemu pengguna sungguhan: pendaftaran, pemesanan, pencarian. Membuatnya di React terlihat sepele sampai Anda menemui validasi, pesan galat, tombol yang dinonaktifkan, dan aksesibilitas. Materi ini membangun form dari dasar yang kokoh, dengan logika validasi yang dapat diuji.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·3 menit baca·Tingkat: Menengah

Sebaiknya sudah paham: useState, event handler

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • membuat input terkendali (controlled) dengan value dan onChange
  • mengelola banyak kolom dengan satu objek state
  • menulis fungsi validasi murni dan mengujinya
  • menampilkan pesan galat hanya setelah pengguna menyentuh kolom
  • menangani submit dan menjaga aksesibilitas (label, aria)

Controlled component

Pada input terkendali, state React adalah sumber kebenaran: nilai input selalu berasal dari state, dan setiap ketikan memperbarui state lewat onChange.

Validasi sebagai fungsi murni

Pisahkan aturan validasi dari komponen. Fungsi murni yang menerima data dan mengembalikan objek galat mudah diuji tanpa React, dan dapat dipakai ulang (juga di server).

Tampilkan galat dengan bijak

  • Jangan menampilkan galat sebelum pengguna menyentuh kolom; form kosong penuh warna merah terasa menegur.
  • Simpan state "touched" per kolom (diisi pada onBlur) dan tampilkan galat hanya untuk kolom yang sudah disentuh atau setelah mencoba submit.
  • Tulis pesan yang menjelaskan cara memperbaiki ("Format surel belum benar", bukan "Invalid").
  • Nonaktifkan tombol kirim hanya bila alasannya jelas; sering lebih baik membiarkan aktif dan menampilkan galat saat submit.

Validasi klien bukan pengganti validasi server

Keamanan

Validasi di browser hanya untuk kenyamanan pengguna; siapa pun dapat melewatinya (alat pengembang, permintaan langsung). Server tetap harus memvalidasi semua masukan dan tidak mempercayai klien. Anda dapat memakai skema yang sama di kedua sisi (misalnya pustaka Zod) agar aturan tidak berbeda.

Pustaka form: kapan perlu

Untuk form kecil, state sendiri sudah cukup. Untuk form besar dengan banyak kolom, validasi bersarang, dan array dinamis, pustaka seperti React Hook Form mengurangi render ulang dan kode berulang. React 19 juga menambahkan Actions dan hook useActionState untuk menangani submit asinkron dan status pending dengan lebih ringkas.

Latihan mandiri
1. Tambahkan kolom "kata sandi" dengan aturan minimal 8 karakter ke fungsi validasi.
if (!data.sandi) galat.sandi = "Kata sandi wajib diisi."; else if (data.sandi.length < 8) galat.sandi = "Minimal 8 karakter.";
2. Mengapa galat sebaiknya dihitung saat render, bukan disimpan di state?
Galat adalah turunan dari data; menyimpannya terpisah dapat tidak sinkron dengan data.
3. Apa bedanya input terkendali dan tak terkendali (uncontrolled)?
Terkendali: nilai di state React. Tak terkendali: nilai disimpan DOM dan dibaca saat dibutuhkan lewat ref atau FormData.
4. Mengapa input perlu label yang terhubung?
Pembaca layar mengumumkan label, dan klik pada label memfokuskan input; ini kebutuhan aksesibilitas dasar.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Input terkendali: value dari state, onChange memperbarui state.
  • Satu objek state dan atribut name memudahkan banyak kolom.
  • Validasi sebagai fungsi murni: mudah diuji dan dipakai ulang.
  • Tampilkan galat setelah kolom disentuh atau submit; pesan harus membantu.
  • Selalu validasi ulang di server; jaga label dan atribut aria.

Tanya jawab

Bagaimana mengunggah berkas di form React?
Input type="file" bersifat tak terkendali; baca e.target.files dan kirim dengan FormData.
Apa itu React Hook Form dan Formik?
Pustaka pengelola form. React Hook Form populer karena memakai input tak terkendali sehingga lebih sedikit render ulang.
Bagaimana mencegah kirim ganda?
Simpan status "sedang mengirim" dan nonaktifkan tombol (atau abaikan submit berikutnya) sampai respons tiba; server sebaiknya idempoten.
