Design System untuk Tim Kecil: Mulai dari Mana?

Tanpa design system, tim kecil cepat menghasilkan tujuh warna biru yang sedikit berbeda, lima gaya tombol, dan jarak yang tidak konsisten. Setiap layar baru dimulai dari nol. Design system tidak harus sebesar Material Design milik Google; versi kecil yang konsisten sudah menghemat banyak waktu desainer dan developer.

Apa isi design system

Mulai dari design tokens

Token adalah keputusan desain yang diberi nama. Alih-alih menulis #1e5ab2 di seratus tempat, semua memakai --warna-utama. Ganti di satu tempat, berubah di mana-mana, termasuk untuk mode gelap.

:root {
  /* primitif */
  --biru-600: #1e5ab2;
  --abu-900: #0f1a33;
  --abu-50: #f5f7fb;

  /* semantik: makna, bukan warna */
  --warna-utama: var(--biru-600);
  --teks: var(--abu-900);
  --latar: var(--abu-50);

  /* jarak berbasis kelipatan 4 */
  --ruang-1: 4px;  --ruang-2: 8px;  --ruang-3: 12px;
  --ruang-4: 16px; --ruang-6: 24px; --ruang-8: 32px;

  --radius: 8px;
  --font-badan: 16px;
}

@media (prefers-color-scheme: dark) {
  :root { --teks: #e8edf7; --latar: #0f1a33; }
}

Komponen inti yang dibuat lebih dulu

  1. Tombol (utama, sekunder, bahaya; status normal, hover, fokus, nonaktif, memuat).
  2. Input teks dengan label, bantuan, dan pesan error.
  3. Pilihan: checkbox, radio, select.
  4. Kartu dan daftar.
  5. Modal atau dialog.
  6. Notifikasi (toast) dan banner.
  7. Navigasi.
Jangan hapus focus ring

Status fokus keyboard sering dilupakan dan dihapus karena "jelek". Tanpa itu, pengguna keyboard tidak tahu posisi mereka di halaman. Rancang status fokus yang jelas dan indah.

Atomic design sebagai cara berpikir

Brad Frost mengusulkan analogi kimia: atom (label, input, tombol) membentuk molekul (kolom pencarian), membentuk organisme (header), lalu template dan halaman. Gunanya untuk menyadari bahwa halaman dibangun dari bagian-bagian yang bisa dipakai ulang.

Menjaga desain dan kode tetap sinkron

  • Satu sumber token: variabel Figma diekspor ke CSS atau JSON (format Design Tokens W3C Community Group).
  • Komponen di kode dan di Figma memakai nama yang sama.
  • Dokumentasi dengan contoh hidup, misalnya Storybook.
  • Proses perubahan: siapa yang boleh menambah komponen, dan bagaimana mengumumkannya.

Tanya jawab

Kapan tim butuh design system?
Begitu ada lebih dari satu desainer atau developer yang membuat layar, atau ketika produk mulai terlihat tidak konsisten.
Apakah Tailwind CSS sudah design system?
Tailwind menyediakan skala token dan utilitas, yang bisa menjadi dasar design system. Anda tetap perlu komponen, pola, dan dokumentasi.
Bagaimana mengukur keberhasilannya?
Waktu membuat layar baru, jumlah komponen yang dipakai ulang, dan berkurangnya bug tampilan yang tidak konsisten.
