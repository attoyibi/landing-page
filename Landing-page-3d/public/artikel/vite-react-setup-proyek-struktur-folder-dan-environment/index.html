React & Web Modern

Vite + React: Setup Proyek, Struktur Folder, dan Env

Create React App sudah tidak lagi direkomendasikan. Vite menjadi pilihan standar untuk proyek React baru karena server pengembangan hampir instan dan build produksi yang efisien. Materi ini membawa Anda dari nol sampai proyek yang rapi, siap dikembangkan dan dideploy.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·3 menit baca·Tingkat: Pemula

Sebaiknya sudah paham: Node.js terpasang, JavaScript dasar

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • membuat proyek React dengan Vite dan memahami berkas yang dihasilkan
  • mengatur struktur folder yang terukur untuk proyek berkembang
  • memakai variabel environment dengan benar dan aman
  • mengatur alias impor dan variabel konfigurasi dasar
  • membangun dan menguji hasil produksi secara lokal

Mengapa Vite

Vite memakai modul ES native di browser selama pengembangan, jadi tidak perlu membundel seluruh aplikasi sebelum bisa dibuka; hanya berkas yang diminta yang diproses (dengan esbuild yang sangat cepat). Hasilnya: server dev menyala hampir seketika dan pembaruan modul panas (HMR) terasa instan. Untuk produksi, Vite membundel dengan Rollup.

Membuat proyek

index.htmlBerada di akar, bukan di public/Tempat title, meta, dan script modul

Struktur folder yang tumbuh dengan sehat

Tidak ada struktur tunggal yang benar, tetapi satu pedoman bertahan baik: kelompokkan menurut fitur, bukan menurut jenis berkas. Mengelompokkan semua komponen di satu folder dan semua hook di folder lain membuat Anda berlari-lari antar folder untuk satu fitur.

Variabel environment

Vite hanya mengekspos variabel berawalan VITE_ ke kode klien, lewat import.meta.env. Variabel tanpa awalan itu tetap rahasia di mesin build.

Bukan tempat rahasia

Semua yang berawalan VITE_ akan terlihat oleh siapa pun yang membuka aplikasi Anda (ia disisipkan ke JavaScript klien). Jangan pernah menaruh kunci rahasia (kunci API privat, kata sandi basis data) di variabel VITE_. Rahasia harus berada di server. Tambahkan .env.local ke .gitignore.

Build produksi dan mengujinya

Deploy: yang perlu diingat

  • SPA fallback: bila memakai routing sisi klien, host harus mengembalikan index.html untuk alamat yang tidak ditemukan (Cloudflare Pages/Workers, Vercel, dan Netlify memiliki pengaturannya).
  • Variabel environment produksi diatur di dashboard host sebelum build, karena nilainya disisipkan saat build.
  • base: bila aplikasi ditaruh di subfolder (misalnya GitHub Pages), atur base di vite.config.
  • Periksa ukuran bundel dengan plugin visualisasi sebelum merilis.
Latihan mandiri
1. Mengapa .env.local tidak boleh dikomit?
Berisi nilai khusus mesin atau rahasia pribadi; tambahkan ke .gitignore.
2. Kapan berkas ditaruh di public/ dan kapan di src/assets/?
public/ untuk berkas dengan alamat tetap (robots.txt, favicon); src/assets/ untuk berkas yang diimpor dan perlu hash serta optimasi.
3. Apa gunanya proxy di server dev?
Meneruskan /api ke backend sehingga tidak ada masalah CORS saat pengembangan.
4. Mengapa struktur berdasarkan fitur lebih mudah dirawat?
Semua file satu fitur berdekatan; mengubah atau menghapus fitur cukup menyentuh satu folder.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Vite: server dev cepat, build produksi dengan Rollup; buat dengan npm create vite.
  • Struktur folder berdasarkan fitur; komponen generik di komponen/, fungsi bantu di lib/.
  • Variabel VITE_ terlihat publik: tidak untuk rahasia.
  • Uji hasil build dengan preview; siapkan SPA fallback dan variabel environment di host.

Tanya jawab

Apa bedanya Vite dan Next.js?
Vite adalah alat build/dev untuk SPA (atau pustaka lain); Next.js adalah framework penuh dengan routing, SSR, dan optimasi bawaan.
Apakah masih ada Create React App?
Sudah tidak dipelihara aktif dan tidak lagi direkomendasikan; React docs menyarankan framework atau Vite.
Bagaimana menambah ESLint dan Prettier?
Templat Vite menyertakan ESLint; tambahkan Prettier dan skrip lint/format, lalu jalankan otomatis dengan hook Git (husky) atau CI.
