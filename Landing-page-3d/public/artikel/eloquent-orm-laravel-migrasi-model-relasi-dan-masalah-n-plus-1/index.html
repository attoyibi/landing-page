Eloquent ORM Laravel: Migrasi, Model, Relasi, dan N+1

Eloquent adalah ORM Laravel: setiap tabel punya model, dan setiap baris menjadi objek. Anda menulis kode PHP yang ekspresif alih-alih SQL mentah. Kemudahan itu menyimpan satu jebakan yang paling sering menyebabkan aplikasi Laravel lambat: masalah N+1 query. Memahaminya adalah pembeda antara aplikasi yang cepat dan yang merayap.

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • membuat tabel dengan migrasi dan memahami manfaat migrasi
  • membuat model dan menulis query dengan Eloquent
  • mendefinisikan relasi satu-ke-banyak dan belongsTo
  • mengenali masalah N+1 dan memperbaikinya dengan eager loading
  • memahami mass assignment dan $fillable
Tentang contoh kode

Kode PHP/Laravel di artikel ini ditampilkan sebagai contoh yang mengikuti dokumentasi Laravel (versi 11 dan seterusnya, PHP 8.2 atau lebih baru). Bagian "cara kerja di balik layar" dijalankan sungguhan dengan Python atau JavaScript agar konsepnya dapat dibuktikan.

Model dan query

Keamanan

Mass assignment: Produk::create($request->all()) tanpa batasan memungkinkan penyerang menyisipkan kolom yang tidak Anda duga (misalnya is_admin). $fillable mendaftar kolom yang boleh diisi massal. Lebih aman lagi, gunakan $request->validated() yang hanya berisi kolom yang lolos validasi.

Masalah N+1: diperagakan

Misalkan halaman menampilkan 100 produk beserta nama kategorinya. Bila kategori diambil satu per satu di dalam perulangan, Anda menjalankan 1 query untuk daftar produk ditambah 100 query untuk kategori: total 101. Berikut peragaan dengan SQL sungguhan (SQLite) yang menghitung jumlah query, setara dengan yang dilakukan Eloquent.

Praktik query yang sehat

  • Ambil hanya yang diperlukan: select("id", "nama") dan paginasi (paginate()) alih-alih all() pada tabel besar.
  • Indeks pada kolom yang sering dipakai di where, order by, dan kunci asing.
  • Pemrosesan besar: chunk() atau lazy() agar tidak memuat jutaan baris ke memori.
  • Transaksi: DB::transaction(fn () => ...) untuk beberapa perubahan yang harus berhasil atau gagal bersama.
  • Jangan menyisipkan input pengguna ke SQL mentah; gunakan binding parameter (query builder dan Eloquent sudah melakukannya).
Latihan mandiri
1. Tulis query Eloquent untuk 20 produk termahal beserta kategorinya tanpa N+1.
Produk::with("kategori")->orderByDesc("harga")->limit(20)->get();
2. Mengapa migrasi lebih baik daripada mengubah tabel manual di phpMyAdmin?
Perubahan skema tercatat di Git, dapat diulang, dan sama di semua lingkungan (lokal, staging, produksi).
3. Kapan memakai withCount?
Saat hanya butuh jumlah relasi; SQL menghitungnya sehingga relasi tidak dimuat ke memori.
4. Bagaimana mendeteksi N+1 sejak dini?
Aktifkan Model::preventLazyLoading di lingkungan non-produksi dan pantau jumlah query dengan Debugbar atau Telescope.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Migrasi menjaga skema basis data tetap terversi; model Eloquent memetakan tabel ke objek.
  • Relasi: hasMany, belongsTo, belongsToMany, polimorfik.
  • N+1: 1 + N query akibat lazy loading; atasi dengan with() (eager loading).
  • Batasi mass assignment, gunakan indeks, paginasi, dan transaksi.

Tanya jawab

Apakah Eloquent lambat dibanding SQL mentah?
Ada overhead kecil membuat objek, tetapi masalah nyata hampir selalu query yang berlebihan (N+1) atau tanpa indeks, bukan ORM itu sendiri. Untuk laporan berat, query builder atau SQL mentah dengan binding tetap boleh dipakai.
Apa itu soft delete?
Menandai baris dihapus (kolom deleted_at) tanpa menghapusnya secara fisik, memakai trait SoftDeletes.
Apa itu seeder dan factory?
Seeder mengisi data awal; factory membuat data palsu untuk pengembangan dan pengujian.
