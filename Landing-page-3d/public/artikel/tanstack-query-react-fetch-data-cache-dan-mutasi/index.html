TanStack Query: Fetch Data, Cache, dan Mutasi di React

Mengambil data dengan useEffect dan useState tampak mudah, sampai Anda butuh status memuat, galat, pembatalan, cache, pengambilan ulang saat jendela kembali aktif, dan pembaruan setelah mutasi. Kode itu cepat membengkak dan penuh jebakan. TanStack Query memperlakukan data server sebagai kategori tersendiri dan menyelesaikan semuanya.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·2 menit baca·Tingkat: Menengah

Sebaiknya sudah paham: useEffect, fetch API dan async/await

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • membedakan state klien dan state server
  • memakai useQuery dengan queryKey dan queryFn
  • memahami cache, staleTime, dan pengambilan ulang otomatis
  • melakukan mutasi dan menginvalidasi cache dengan useMutation
  • menjelaskan apa yang dihemat dibanding fetch manual

Cara kerja cache: fresh, stale, dan refetch

Data di cache dianggap fresh selama staleTime (bawaan 0). Setelah itu stale: masih ditampilkan seketika dari cache, sementara di latar belakang diambil ulang (stale-while-revalidate). Pengambilan ulang otomatis terjadi saat komponen baru dipasang, jendela mendapat fokus kembali, atau koneksi pulih.

OpsiFungsi
staleTimeBerapa lama data dianggap segar (tidak diambil ulang)
gcTimeBerapa lama data tak terpakai disimpan di cache sebelum dibuang
retryJumlah percobaan ulang bila gagal
enabledMenunda query sampai kondisi terpenuhi (misalnya id tersedia)
placeholderData / initialDataData sementara agar tampilan tidak kosong
selectMengubah atau memilih bagian dari data sebelum sampai ke komponen

Mutasi dan invalidasi

Terasa instan

Pembaruan optimistis: untuk aksi yang hampir pasti berhasil (menyukai, mencentang), perbarui tampilan seketika dengan onMutate dan kembalikan bila gagal di onError. Terasa instan bagi pengguna, tetapi tangani kegagalan dengan jujur.

Kapan tidak perlu

  • Aplikasi kecil dengan satu atau dua permintaan sederhana: fetch + useEffect (dengan pembatalan) cukup.
  • Bila memakai framework dengan pemuatan data bawaan (loader Next.js, Remix, Server Components), sebagian peran ini sudah ditangani framework.
  • Data murni klien (state UI) bukan tugas pustaka ini.
Latihan mandiri
1. Tulis queryKey untuk daftar produk berfilter kategori dan halaman.
["produk", { kategori, halaman }]: perubahan filter otomatis membuat entri cache terpisah.
2. Mengapa query dengan id undefined perlu opsi enabled?
Agar tidak mengirim permintaan sampai id tersedia: enabled: !!id.
3. Apa keuntungan berbagi queryKey antar komponen?
Satu permintaan, satu cache; semua komponen yang memakai kunci itu menerima pembaruan yang sama.
4. Kapan menaikkan staleTime?
Bila data jarang berubah (daftar negara, konfigurasi) sehingga pengambilan ulang tidak diperlukan.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Pisahkan state klien dari state server; yang kedua punya masalah cache dan sinkronisasi.
  • useQuery: queryKey + queryFn memberi data, status, dan galat; cache dibagi lewat kunci.
  • staleTime dan stale-while-revalidate: tampil seketika, segarkan di latar.
  • useMutation + invalidateQueries menjaga tampilan sinkron setelah perubahan.

Tanya jawab

Apa bedanya TanStack Query dan SWR?
Keduanya serupa (stale-while-revalidate). TanStack Query punya fitur lebih lengkap (mutasi, paginasi infinit, devtools); SWR lebih ringkas.
Apakah tetap butuh Redux?
Untuk data server tidak lagi; Redux/Zustand tetap berguna bagi state klien kompleks, tetapi banyak aplikasi tidak membutuhkannya.
Apakah mendukung rendering di server?
Ya, dengan prefetch dan dehydrate/hydrate sehingga data awal sudah ada saat halaman sampai ke browser.
