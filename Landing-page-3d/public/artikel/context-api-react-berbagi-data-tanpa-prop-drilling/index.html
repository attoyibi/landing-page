Context API React: Berbagi Data Tanpa Prop Drilling

Mengirim props lewat lima tingkat komponen hanya agar komponen paling dalam bisa membaca tema atau pengguna yang login itu melelahkan, dan merusak keterbacaan. Context menyediakan jalur pintas: nilai ditaruh di satu titik pohon dan dibaca oleh komponen di bawahnya. Namun Context bukan pengganti semua state management.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·2 menit baca·Tingkat: Menengah

Sebaiknya sudah paham: props, useState, useReducer

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • menjelaskan prop drilling dan kapan menjadi masalah
  • membuat dan memakai Context dengan createContext, Provider, dan useContext
  • memadukan Context dengan useReducer untuk state aplikasi
  • mengenali jebakan performa Context dan cara mengurangi render ulang
  • memilih antara Context, props, composition, dan pustaka state eksternal

Masalah: prop drilling

Context: tiga langkah

  1. Buat context dengan createContext(nilaiBawaan).
  2. Sediakan nilainya dengan <Context.Provider value=...> di atas komponen yang membutuhkan.
  3. Baca dengan useContext(Context) di komponen mana pun di bawah Provider.

Pola yang rapi: Provider + hook khusus

Bungkus context dalam modul sendiri: Provider yang mengelola state, dan hook khusus yang memberi pesan galat bila dipakai di luar Provider.

Jebakan: semua pembaca ikut render ulang

Saat nilai value pada Provider berubah, setiap komponen yang memanggil useContext(context itu) dirender ulang, walau ia hanya memakai sebagian nilai. Dan membuat objek baru di value={{ ... }} setiap render membuat nilainya selalu "berubah".

  • Pecah context menurut seberapa sering berubah: konteks tema (jarang) terpisah dari konteks keranjang (sering).
  • Pisahkan state dan dispatch ke dua context agar komponen yang hanya mengirim aksi tidak ikut render saat state berubah.
  • Stabilkan nilai dengan useMemo bila Provider sendiri sering dirender ulang oleh induknya.
  • Pertimbangkan composition: kirim komponen sebagai children atau props agar perantara tidak perlu mengenal data.

Kapan memakai apa

KebutuhanPilihan
Data jarang berubah dan dipakai di banyak tempat (tema, bahasa, pengguna)Context
Data hanya dipakai satu atau dua tingkat di bawahProps biasa
Perantara hanya meneruskan elemenComposition (children)
State global besar yang sering berubah dan perlu pembaruan selektifPustaka state (Zustand, Redux Toolkit, Jotai)
Data dari server dengan cacheTanStack Query atau SWR, bukan Context
Salah kaprah

Context bukan alat manajemen state sendirian; ia adalah mekanisme pengiriman nilai. State tetap berasal dari useState atau useReducer. Jangan memasukkan semua state aplikasi ke satu context raksasa.

Latihan mandiri
1. Buat context bahasa ("id" atau "en") dengan tombol untuk mengganti.
Provider memegang useState("id") dan menyediakan { bahasa, setBahasa }; komponen membaca dengan useContext.
2. Mengapa membungkus useContext dalam hook khusus berguna?
Menyembunyikan detail, memberi pesan galat jelas di luar Provider, dan memudahkan mengganti implementasi.
3. Kapan composition lebih baik daripada Context?
Saat hanya satu atau dua tingkat perantara; mengirim JSX sebagai children menghindari ketergantungan global.
4. Mengapa memisahkan context state dan dispatch mengurangi render?
Komponen yang hanya memanggil dispatch (stabil) tidak berlangganan state, sehingga tidak dirender ulang saat state berubah.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Context mengirim nilai ke komponen mana pun di bawah Provider tanpa melewati props.
  • createContext, Provider, useContext; bungkus dalam Provider dan hook khusus.
  • Nilai berubah → semua pembaca ikut render ulang; pecah context dan stabilkan nilai.
  • Context bukan pengganti state management dan bukan cache data server.

Tanya jawab

Apa bedanya Context dan Redux?
Context hanya mengirim nilai; Redux menyediakan penyimpanan terpusat, pola aksi-reducer, middleware, dan devtools, dengan pembaruan selektif yang efisien.
Bolehkah memakai beberapa Provider?
Boleh dan umum; urutan bersarang menentukan context mana yang tersedia bagi komponen di dalamnya.
Apakah Context bekerja saat rendering di server?
Ya, seperti contoh di atas yang dijalankan dengan renderToString.
