Laravel & Backend

Caching dan Performa Laravel: Cache, Optimize, dan Index

Aplikasi lambat jarang disebabkan PHP itu sendiri. Hampir selalu penyebabnya adalah terlalu banyak query, query tanpa indeks, atau pekerjaan berulang yang tidak perlu diulang. Urutan kerjanya: ukur, perbaiki query dan indeks, baru kemudian gunakan cache untuk hal yang benar-benar mahal. Cache yang ditambahkan terlalu dini hanya menyembunyikan masalah dan menambah bug basi.

Sebaiknya sudah paham: Eloquent, N+1 query

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • mengukur sebelum mengoptimasi (query, waktu respons)
  • memperbaiki N+1 dan menambah indeks yang tepat
  • memakai pola cache-aside dengan Cache::remember dan TTL
  • merancang invalidasi cache agar data tidak basi
  • memakai optimasi produksi: config, route, view cache, dan opcache
Tentang contoh kode

Kode PHP/Laravel di artikel ini mengikuti dokumentasi Laravel (versi 11 dan seterusnya, PHP 8.2 atau lebih baru). Bagian "cara kerja di balik layar" dijalankan sungguhan dengan Python atau JavaScript agar konsepnya dapat dibuktikan.

Urutan optimasi

  1. Ukur: waktu respons, jumlah query per halaman, query paling lambat (Debugbar, Telescope, log query, APM seperti Sentry atau New Relic).
  2. Kurangi query: perbaiki N+1 dengan eager loading, ambil kolom seperlunya, paginasi.
  3. Percepat query: tambah indeks pada kolom where, join, order by.
  4. Cache hasil yang mahal dan jarang berubah.
  5. Pindahkan pekerjaan berat ke antrean.
  6. Optimasi server: opcache, cache konfigurasi, PHP-FPM yang disetel, CDN untuk aset.

Kebocoran lewat cache

Jangan menyimpan data khusus pengguna dalam kunci cache umum: misalnya Cache::remember("keranjang", ...) tanpa ID pengguna akan menampilkan keranjang orang lain. Sertakan semua variabel yang memengaruhi hasil (pengguna, bahasa, halaman, filter) di kunci.

Optimasi produksi bawaan Laravel

Daftar periksa performa

Latihan mandiri
1. Halaman beranda menampilkan 12 produk dan nama kategori masing-masing; berapa query jika N+1? Berapa dengan eager loading?
N+1: 1 + 12 = 13 query. Eager loading: 2 query.
2. Query WHERE status = ? ORDER BY created_at lambat; indeks seperti apa?
Indeks gabungan (status, created_at): kolom filter lebih dulu, lalu kolom pengurutan.
3. Mengapa env() jangan dipakai di luar berkas config setelah config:cache?
Saat config di-cache, .env tidak dibaca lagi sehingga env() mengembalikan null; baca lewat config().
4. Kapan TTL pendek cukup tanpa invalidasi eksplisit?
Bila data boleh sedikit basi (statistik, daftar terlaris) dan lebih penting kesederhanaan.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Ukur dulu; perbaiki N+1 dan indeks sebelum menambah cache.
  • Cache::remember (cache-aside) dengan TTL dan invalidasi; kunci memuat semua variabel penentu hasil.
  • php artisan optimize, opcache, dan autoloader teroptimasi di produksi; APP_DEBUG=false.
  • Pindahkan pekerjaan berat ke antrean; gunakan Redis dan CDN untuk skala.

Tanya jawab

Apa itu Octane?
Laravel Octane menjalankan aplikasi di server berkinerja tinggi (FrankenPHP, Swoole, RoadRunner) yang menyimpan aplikasi di memori antar permintaan sehingga jauh lebih cepat, dengan kehati-hatian soal keadaan global.
Redis wajib?
Tidak untuk aplikasi kecil; cache file atau database cukup. Redis menjadi pilihan saat butuh kecepatan, tag cache, antrean, dan sesi bersama.
Bagaimana menemukan query paling lambat?
Aktifkan slow query log di basis data, gunakan Telescope atau APM, dan periksa EXPLAIN pada query tersebut.
