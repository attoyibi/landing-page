useReducer React: Kelola State Kompleks dengan Reducer

Ketika satu komponen mulai memiliki lima state yang saling terkait dan tujuh fungsi yang mengubahnya, kode menjadi sulit diikuti. useReducer memusatkan semua cara state berubah di satu tempat, dalam sebuah fungsi murni yang mudah dibaca dan diuji. Pola yang sama menjadi inti Redux.

Sebaiknya sudah paham: useState, render list

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • menjelaskan pola reducer: (state, action) → state baru
  • memakai useReducer pada komponen React
  • memilih antara useState dan useReducer
  • menulis dan menguji reducer sebagai fungsi murni
  • menangani aksi tak dikenal dan status asinkron secara terstruktur

Reducer: satu fungsi untuk semua perubahan

Reducer menerima state sekarang dan sebuah aksi (objek yang menjelaskan apa yang terjadi), lalu mengembalikan state baru. Ia murni: tanpa efek samping, tanpa mengubah state lama. Karena murni, ia bisa dijalankan dan diuji di luar React.

Pedoman

Tidak ada aturan keras. Mulai dengan useState; pindah ke useReducer ketika Anda mendapati handler yang bolak-balik mengubah banyak state sekaligus atau ketika pembaruan state mulai sulit dipahami.

Menguji reducer tanpa React

State asinkron: modelkan statusnya

Alih-alih tiga state terpisah (memuat, data, galat) yang bisa saling bertentangan (memuat dan galat sekaligus?), modelkan satu status dengan kemungkinan terbatas.

Latihan mandiri
1. Tambahkan aksi "hapus" yang menghapus item ber-id tertentu dari keranjang.
case "hapus": return { ...state, item: state.item.filter(i => i.id !== aksi.id) };
2. Mengapa reducer tidak boleh memanggil fetch?
Reducer harus murni dan deterministik; permintaan jaringan adalah efek samping yang dilakukan di event handler atau efek, lalu hasilnya dikirim sebagai aksi.
3. Apa yang terjadi bila reducer mengubah state langsung dan mengembalikan objek yang sama?
React menganggap tidak ada perubahan (referensi sama) dan tidak merender ulang; mode pengembangan juga bisa memanggil reducer dua kali sehingga mengungkap bug.
4. Berikan dua keuntungan menamai aksi.
Alur perubahan mudah dilacak dan didebug, serta daftar aksi menjadi dokumentasi perilaku state.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Reducer: (state, aksi) → state baru, fungsi murni.
  • useReducer mengembalikan [state, dispatch]; komponen mengirim aksi, reducer menentukan perubahan.
  • Pilih bila state saling terkait atau jenis perubahan banyak; reducer mudah diuji tanpa React.
  • Modelkan status asinkron sebagai satu nilai status untuk menghindari keadaan mustahil.

Tanya jawab

Apa hubungan useReducer dengan Redux?
Redux memakai pola reducer yang sama, tetapi dengan satu penyimpanan global dan alat bantu (devtools, middleware). useReducer bersifat lokal pada komponen, kecuali digabung dengan Context.
Apakah dispatch berubah antar render?
Tidak; identitas dispatch stabil sehingga aman diteruskan ke anak atau dimasukkan ke dependency.
Bagaimana menangani efek samping pada aksi?
Lakukan di event handler atau useEffect, lalu kirim aksi hasilnya (misalnya sukses atau gagal).
