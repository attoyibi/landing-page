useState React: Apa Itu State dan Bagaimana Cara Kerjanya

Komponen yang hanya menampilkan props itu statis. Untuk membuatnya hidup, yaitu bereaksi pada klik, ketikan, atau data masuk, React memberi komponen ingatan bernama state. useState adalah pintu masuk ke sana, dan memahami cara kerjanya menghindarkan Anda dari sebagian besar bug pemula.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·2 menit baca·Tingkat: Pemula

Sebaiknya sudah paham: komponen, JSX, dan props

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • menjelaskan perbedaan props dan state
  • memakai useState untuk menyimpan dan memperbarui data
  • menjelaskan mengapa variabel biasa tidak membuat tampilan berubah
  • memahami state sebagai potret (snapshot) dan pembaruan fungsional
  • menghindari kesalahan umum: mengubah state langsung, state turunan, dan batch update

Masalah: variabel biasa tidak cukup

Coba buat penghitung dengan variabel biasa. Fungsi komponen dijalankan ulang setiap kali React merender; variabel lokal dibuat dari awal tiap kali, dan mengubahnya tidak memicu render.

useState: ingatan yang memicu render

Aturan hooks

Aturan hook: panggil hook (useState, useEffect, ...) di tingkat paling atas komponen, bukan di dalam kondisi, perulangan, atau fungsi bersarang. React mengenali state berdasarkan urutan pemanggilannya.

Mengintip cara kerjanya dengan useState mini

React menyimpan state di luar fungsi komponen, per komponen dan per urutan hook. Berikut tiruan sangat disederhanakan (bukan kode React sebenarnya) untuk menunjukkan idenya.

State adalah potret

Di dalam satu render, nilai state tidak berubah. Memanggil setter menjadwalkan render berikutnya dengan nilai baru, bukan mengubah variabel yang sedang Anda baca.

Hindari state turunan

Jangan menyimpan di state sesuatu yang bisa dihitung dari props atau state lain. Misalnya simpan daftar dan kataCari, lalu hitung hasilFilter saat render. Menyimpannya terpisah menciptakan dua sumber kebenaran yang bisa tidak sinkron.

Latihan mandiri
1. Tulis state untuk toggle "tampilkan detail" dan tombol yang membaliknya.
const [buka, setBuka] = useState(false); ... onClick={() => setBuka(b => !b)}
2. Tambahkan item ke state array daftar tanpa mengubah aslinya.
setDaftar([...daftar, itemBaru]) atau setDaftar(d => [...d, itemBaru])
3. Ubah properti "selesai" pada tugas ber-id 2 dalam array tugas.
setTugas(t => t.map(x => x.id === 2 ? { ...x, selesai: true } : x))
4. Mengapa nilai awal useState(hitungBerat()) boros dan apa solusinya?
hitungBerat() dipanggil di setiap render walau hasilnya hanya dipakai sekali. Pakai inisialisasi malas: useState(() => hitungBerat()).
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • State adalah ingatan komponen; useState memberi [nilai, setter] dan setter memicu render.
  • State adalah potret per render; pakai update fungsional bila bergantung pada nilai sebelumnya.
  • Jangan ubah objek atau array state langsung; buat salinan baru.
  • Panggil hook di tingkat atas; hindari menyimpan data yang bisa dihitung dari state lain.

Tanya jawab

Apa bedanya useState dan useRef?
Mengubah ref tidak memicu render ulang; useRef cocok untuk menyimpan nilai yang tidak memengaruhi tampilan (elemen DOM, id timer).
Mengapa console.log setelah setState menampilkan nilai lama?
Karena state adalah potret untuk render saat ini; nilai baru baru terlihat pada render berikutnya.
Kapan memakai useReducer?
Saat logika pembaruan state rumit atau banyak aksi berbeda mengubah state yang saling terkait.
