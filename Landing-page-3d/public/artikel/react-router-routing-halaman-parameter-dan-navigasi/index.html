React Router: Routing Halaman, Parameter, dan Navigasi

Aplikasi React biasa berupa satu halaman HTML (single-page application). Routing membuat pengguna tetap merasakan banyak halaman: alamat di bilah browser berubah, tombol kembali berfungsi, dan setiap tampilan dapat dibagikan lewat tautan. React Router adalah pustaka routing yang paling banyak dipakai.

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • menjelaskan bagaimana SPA mengelola banyak halaman
  • mendefinisikan rute, Link, dan nested route dengan React Router
  • membaca parameter dinamis dan query string
  • menangani redirect, halaman 404, dan navigasi terprogram
  • memahami logika pencocokan path dengan implementasi sederhana

Bagaimana SPA "berpindah halaman"

Alih-alih meminta HTML baru dari server, SPA memakai History API browser untuk mengubah alamat tanpa muat ulang, lalu memilih komponen mana yang tampil berdasarkan alamat. Karena itu tautan harus memakai komponen Link (bukan <a href> biasa) agar tidak memuat ulang seluruh halaman.

Bagaimana pencocokan path bekerja

Di balik layar, router memecah path menjadi segmen dan membandingkannya dengan pola rute: segmen biasa harus sama persis, :nama mencocokkan apa saja dan menjadi parameter, dan * mencocokkan sisanya. Implementasi mini berikut menunjukkan idenya dan bisa Anda jalankan.

Hal praktis yang sering terlewat

  • Server harus mengembalikan index.html untuk semua alamat (SPA fallback); bila tidak, membuka /produk/42 langsung memberi 404. Cloudflare Pages dan Vercel menyediakan pengaturan ini, atau gunakan HashRouter sebagai cadangan.
  • Pindah halaman harus mengembalikan fokus dan gulir ke atas; tanpa ini pengguna pembaca layar tidak tahu halaman berganti.
  • Judul dokumen perlu diperbarui per rute agar tab dan riwayat bermakna.
  • SEO: halaman SPA murni dirender di browser; bila penting bagi mesin pencari, pakai rendering di server atau prerender (Next.js, Remix, React Router framework mode).
  • Rute yang dilindungi (butuh login) dikerjakan dengan komponen pembungkus yang mengalihkan dengan <Navigate to="/masuk" replace /> bila belum masuk.
Latihan mandiri
1. Tulis rute untuk halaman profil di /pengguna/:nama dan baca namanya.
<Route path="/pengguna/:nama" element={<Profil />} /> dan const { nama } = useParams();
2. Apa bedanya parameter path dan query string?
Parameter path mengidentifikasi sumber daya (/produk/42); query string menyaring atau mengatur tampilan (?urut=murah).
3. Bagaimana mengalihkan pengguna yang belum login dari rute terlindungi?
Komponen pembungkus memeriksa status login dan mengembalikan <Navigate to="/masuk" replace /> bila belum masuk.
4. Mengapa halaman SPA murni kurang ideal untuk SEO dan apa alternatifnya?
Konten dirender di browser sehingga tidak selalu terbaca penjelajah sederhana; gunakan SSR/SSG atau prerender.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • SPA mengganti tampilan lewat History API tanpa muat ulang; gunakan Link/NavLink.
  • Routes, Route, parameter :id, useParams, useSearchParams, useNavigate, Outlet untuk tata letak bersarang.
  • Pencocokan path membandingkan segmen; rute cadangan "*" untuk 404.
  • Siapkan SPA fallback di server, kelola fokus dan judul halaman, dan pikirkan SEO.

Tanya jawab

Apa bedanya BrowserRouter dan HashRouter?
BrowserRouter memakai alamat bersih (/produk) dan butuh SPA fallback di server; HashRouter memakai /#/produk dan bekerja tanpa konfigurasi server.
Apakah React Router satu-satunya pilihan?
Ada alternatif seperti TanStack Router, dan framework dengan routing berbasis berkas (Next.js, Remix).
Apa itu loader dan action?
Pada mode data React Router, loader mengambil data sebelum rute tampil dan action menangani submit form, sehingga pengambilan data terintegrasi dengan routing.
