Testing Flutter: Unit, Widget, dan Integration Test

Tanpa tes, setiap perubahan adalah taruhan: memperbaiki satu layar bisa merusak layar lain tanpa ketahuan sampai pengguna mengeluh. Flutter menyediakan tiga tingkat pengujian dengan biaya dan manfaat berbeda. Kuncinya memilih tingkat yang tepat untuk setiap jenis kode.

Oleh Muhammad Muchson Attoyibi·30 Oktober 2026·2 menit baca·Tingkat: Menengah

Sebaiknya sudah paham: dasar Dart, widget Flutter

Tujuan belajar

Setelah membaca dan mencoba materi ini, Anda mampu:

  • menjelaskan perbedaan unit, widget, dan integration test
  • menerapkan piramida pengujian pada aplikasi Flutter
  • menulis unit test dengan pola Arrange-Act-Assert
  • memakai fake dan mock untuk memisahkan dependensi
  • mengenal golden test dan menjalankan semua tes dengan flutter test
Tentang contoh kode

Contoh Flutter ditampilkan sebagai kode yang mengikuti dokumentasi Flutter 3.x. Logika Dart murni dijalankan sungguhan dengan Dart SDK; kode yang butuh Flutter (widget, uji widget) tidak dijalankan di halaman ini.

Piramida

Banyak di bawah, sedikit di atas: tes bawah cepat dan stabil sehingga bisa dijalankan setiap simpan; tes atas lambat dan rapuh sehingga cukup untuk alur kritis.

Integration test dan golden test

  • Integration test (paket integration_test) menjalankan aplikasi utuh di emulator/perangkat dan menggerakkannya seperti pengguna. Jalankan: flutter test integration_test. Pakai untuk 3-5 alur kritis (daftar, masuk, beli).
  • Golden test membandingkan tangkapan layar widget dengan berkas gambar acuan: await expectLater(find.byType(Kartu), matchesGoldenFile("kartu.png")). Perbarui acuan dengan flutter test --update-goldens. Berguna untuk mencegah regresi visual, tetapi rapuh antar platform.
  • Cakupan: flutter test --coverage menghasilkan lcov. Cakupan adalah petunjuk, bukan tujuan; 100% cakupan dengan tes tanpa asersi tidak berarti.
  • CI: jalankan flutter analyze dan flutter test pada setiap pull request.
Latihan mandiri
1. Tulis tiga kasus uji untuk fungsi yang memvalidasi umur 17-100.
Batas bawah (17 valid, 16 tidak), batas atas (100 valid, 101 tidak), dan input bukan angka.
2. Mengapa setUp penting dalam group?
Memberi keadaan baru pada tiap tes sehingga tidak saling bergantung.
3. Kapan golden test berguna?
Untuk widget dengan tampilan penting yang tidak boleh berubah tak sengaja (kartu, tema); hati-hati dengan perbedaan font antar platform.
4. Apa risiko integration test berlebihan?
Lambat dan rapuh sehingga pengembang mulai mengabaikannya; batasi pada alur kritis.
Coba kerjakan dulu sebelum membuka jawaban.
Ringkasan
  • Tiga tingkat: unit (banyak, cepat), widget (cukup), integration (sedikit, kritis).
  • Pola Arrange-Act-Assert; satu tes satu perilaku; uji nilai batas dan galat.
  • Pisahkan dependensi lewat antarmuka dan fake/mocktail.
  • Jalankan flutter analyze dan flutter test di CI.

Tanya jawab

Apakah wajib TDD?
Tidak wajib, tetapi menulis tes bersamaan dengan kode (terutama untuk logika) membuat desain lebih mudah diuji.
Berapa target cakupan?
Tidak ada angka ajaib; fokus pada logika bisnis dan alur kritis, 70-80% pada logika sudah baik.
Bagaimana menguji kode async dan Stream?
Gunakan async/await dalam tes, expectLater dengan emitsInOrder untuk Stream.
