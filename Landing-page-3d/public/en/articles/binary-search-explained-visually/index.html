Binary Search Explained Visually: Search by Halving

Guessing a number from 1 to 100 with "higher" or "lower" hints? The best strategy is always to guess in the middle. That is binary search: each step throws away half the possibilities, so data of any size is still searched quickly.

By Muhammad Muchson Attoyibi·October 23, 2026·1 min read

Key takeaways

  • Take the middle value of the remaining range, compare it with the target, throw away the half that cannot contain it and repeat.
  • It needs sorted data; without an order, discarding half is not valid.
  • It takes about log₂(n) steps, which is O(log n): about 20 steps for a million items.
  • Sorting first also costs time, so for a single search on random data, linear search can be simpler.

The idea: throw away half at every step

How fast is it?

Linear search checks one by one: for n items, the worst case is n steps. Binary search checks about log₂(n) steps. For a million items that is about 20 steps, not a million. That is why binary search is called O(log n).

An important condition

Binary search only works when the data is already sorted. Sorting first also takes time, so for a single search on random data, linear search can be simpler.

Where is binary search used?

  • Finding a word in a dictionary, or sorted data in a database (an index).
  • Guessing a parameter, for example finding the first version that introduced a bug (git bisect).
  • Built-in functions in programming languages for sorted data (for example the bisect module in Python).

FAQ

What is the difference between binary search and linear search?
Linear checks one by one, binary halves the range at every step. Binary is much faster on large sorted data.
Can binary search be used for text?
Yes, as long as the data is sorted by the same rule as the comparison being used.
Why is mid computed with (lo + hi) // 2?
It is the middle of the range. In languages with limited integers, the formula lo + (hi - lo) // 2 avoids overflow.
